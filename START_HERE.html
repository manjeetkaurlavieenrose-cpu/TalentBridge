TalentBridge: start here

This folder is the whole application. Nothing needs to be bought, and you do not need to be a developer. Follow the box for your computer.

On a Windows computer

  1. Once only: install Python. Go to python.org/downloads, download Python, run the installer and tick the box “Add python.exe to PATH” on its first screen before pressing Install.
  2. In this folder, double-click start_demo_windows.bat. The first time it sets itself up (a few minutes, it needs the internet). If Windows shows a blue “Windows protected your PC” box, click More info, then Run anyway.
  3. Your browser opens http://localhost:5050 with the demo. Keep the black window open while you use the app; close it to stop the app.

For real use (your own data, kept in the data folder) double-click start_windows.bat instead.

On a Mac

  1. Once only: install Python from python.org/downloads (run the installer with the default choices).
  2. In this folder, right-click start_demo_mac.command and choose Open, then Open again. (A plain double-click is refused the first time because the file came from the internet.)
  3. Your browser opens http://localhost:5050. Keep the Terminal window open while you use the app; close it to stop the app.

For real use double-click start_mac.command instead.

Switching on the AI (free, no subscription, no account)

The app works straight away with its built-in engine. To have a real AI model read CVs, write the skill tests and score answers:

  1. Install Ollama from ollama.com/download. It is a free program that runs the AI on your own computer. (On Windows the setup tries to install it for you.)
  2. Start TalentBridge again. It finds Ollama by itself and downloads the AI model once (about 2 GB, so the first time takes a while). There is nothing to configure.
  3. To check: the black/Terminal window says “AI engine: ollama model qwen2.5:3b …”, and results in the app are labelled “AI-assisted (local model …)”. If a result says “Rule-based”, the model was not ready yet for that result.

The computer should have at least 8 GB of memory. On an ordinary laptop the AI takes roughly half a minute to a minute per step. Nothing is sent to the internet: CVs stay on the computer.

What you can show

  • Candidates upload a CV, see and correct what was read from it, check how they match an opening, apply, and take a short written skill test.
  • Recruiters get an “evidence file” for each applicant: the match with the CV text behind it, every test answer with its score, and their own decision panel.
  • During the test, candidates get a calm on-screen warning if they leave the page, keep the pointer outside it, or paste text; the recruiter sees the counts. When 3 or more candidates give the same answer, the recruiter is told.
  • Originality checks: CVs that share a template or text with other applicants, a second account of the same person, and test answers copied between candidates are shown side by side with the matching passages.
  • The recruiter decides: mark a finding “not a concern” or “a concern”, offer a second attempt, send a follow-up message, shortlist or reject. Nothing is accepted or rejected automatically.

Putting it on GitHub and getting a link anyone can open

GitHub keeps the files. A free hosting service (Render) runs the app and gives you the link. About 15 minutes, no coding.

  1. Make two free accounts: github.com (Sign up) and render.com (choose “Sign up with GitHub”).
  2. Install GitHub Desktop from desktop.github.com and sign in with your GitHub account. (The github.com website only accepts 100 files at a time; this folder has more, so the Desktop app is the easy way.)
  3. In GitHub Desktop: File → Add local repository… → choose this TalentBridge folder. It says the folder is not a repository yet: click create a repository, then Create repository.
  4. Click Publish repository (top bar). Untick “Keep this code private” if you want others to see it. Click Publish.
  5. Wait 2 minutes. GitHub fills in the links in the README by itself. On github.com, open your repository, scroll to Put it online and click Deploy to Render.
  6. Render asks you to confirm: click Apply (or Deploy). After 5–10 minutes it shows your link, such as https://talentbridge-xxxx.onrender.com. Share that link.

The free Render plan sleeps when nobody uses it, so the first visit after a quiet spell takes about a minute, and it restarts with fresh fictional demo data. That is fine for showing the platform; for real candidates see docs/DEPLOY_ANYWHERE.md. Online, the AI part runs on the built-in rule engine unless an AI service is connected (same page).

Sharing it with someone else

  • To give someone the application: send them the zip file you received (the same single file). They unzip it and open this page.
  • To give people a link, follow the GitHub box above.
  • Before sharing a copy you have used, delete the data and demo-data folders so that no uploaded CVs travel with it.

If something goes wrong

  • “Python was not found”: Python is not installed, or the “Add python.exe to PATH” box was not ticked. Install it again with the box ticked.
  • “Port 5050 is already in use”: the app is already running in another window. Use that one, or close it and start again.
  • The page does not open by itself: open your browser and type localhost:5050.
  • To check everything on your computer, double-click test_windows.bat or test_mac.command. It runs the full set of checks and ends with PASSED or FAILED.
  • More help: WINDOWS_SETUP_GUIDE.md and MAC_SETUP_GUIDE.md (they open in Notepad or TextEdit).

Good to know

  • The originality checks compare wording. They do not claim to know whether a person or an AI wrote something; they show what matches what and leave the judgement to you.
  • Messages to candidates always appear in the candidate’s account. They are also e-mailed only after an e-mail service has been connected (see README.md).
  • Before using it with real applicants, read the “Readiness” part of AUDIT_REPORT.md: privacy notice, consent and secure hosting still have to be arranged by your institution.

What was tested, and what could not be tested, is written down honestly in AUDIT_REPORT.md. What changed is in CHANGES.md.
